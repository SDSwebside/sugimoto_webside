# 本地報名系統與正式上線規劃

目前已完成本地版：Node API 將課程報名申請寫入 `.local-data/` 裡的 PGlite 資料庫，並回傳受理編號；一位管理者可登入 `/admin` 查看申請、更新狀態與內部備註。網站頁尾有後台入口。測試報名已清除。本地版不寄送通知郵件，也不會隨 Git 推送而取得線上收件能力。

以下課程、文案、文章及通知功能屬於正式版規劃，尚未建置。

## 公開網站如何使用資料

規劃中的 `site_copy` 用於已存在頁面的短文案，不承載文章。未來管理者修改草稿、預覽並發布後，公開網站才顯示已發布版本。前端將依固定鍵值讀取，例如：

| 鍵值範例 | 前端位置 |
| --- | --- |
| `home.hero.title`、`home.hero.description` | 首頁主標題與介紹。 |
| `services.hero.title`、`services.hero.description` | 服務項目頁開頭。 |
| `cip.hero.title`、`cip.hero.description` | CIP 頁開頭。 |
| `about.hero.title`、`about.hero.description` | 關於我們頁開頭。 |
| `journal.hero.description` | 「工程師的心內話」頁開頭。 |

正式版預計讓課程卡片及報名頁讀取 `courses`，讓「工程師的心內話」讀取 `posts`。文章將有標題、網址代碼、摘要、內文、分類、封面圖、發布時間及草稿／已發布狀態。目前課程資料仍在 `src/features/cip/data.ts`，文章頁顯示「文章整理中」。

接上內容 API 時，先將現有文案與課程匯入資料庫，頁面再改讀已發布資料，避免上線時出現空白區塊。

## 線上報名與後台收件

1. 使用者在課程頁選擇培訓方向，填寫姓名、電郵、電話及備註。
2. 前端呼叫同網域 `POST /api/registrations`。目前 API 驗證資料後寫入本機 PGlite，回傳受理編號；頁面顯示「已收到報名申請」。
3. 本機管理後台可查看詳細資料，標記「待聯繫／聯繫中／已確認／已取消」並加內部備註。課程篩選尚未加入。
4. 正式版才會加入伺服器端郵件通知，寄至 `sugimoto01.com@domainsbyproxy.com`，並記錄寄送與重試狀態。

目前課程尚無核定梯次、名額與時數，因此本地版是**報名申請**；送出不等於已取得名額。管理者確認梯次後再將狀態改為「已確認」。日後若提供固定開課日期與名額，再加入 `course_sessions`，讓使用者選梯次並檢查額滿狀態。一般服務詢問的 `POST /api/inquiries` 尚未建置。

## PostgreSQL 資料表草案

| 資料表 | 用途與主要欄位 |
| --- | --- |
| `registrations`（已建） | 受理編號、`course_id`、姓名、電郵、電話、備註、處理狀態、內部備註、建立時間。 |
| `inquiries` | 一般服務詢問的聯絡資料、需求內容、狀態與建立時間。 |
| `notification_outbox` | 報名／詢問通知的寄送狀態、重試次數、服務商訊息 ID 與最後錯誤。 |
| `courses` | 課程代碼、標題、介紹、對象、培訓重點、排序、草稿與已發布版本。 |
| `site_copy` | 文案鍵值、草稿文字、已發布文字、最後更新時間。 |
| `posts` | 文章網址代碼、標題、摘要、內文、分類、封面圖、草稿／已發布狀態與發布時間。 |
| `content_revisions` | 課程、文案及文章的修改紀錄，便於回復。 |
| `admin_users` | 正式版管理者身分與角色。本地版只有一組以 scrypt 雜湊保存在 `.local-data/admin.json` 的密碼。 |

本地報名資料已依建立時間、狀態及課程建立索引；API 使用參數化查詢、提交頻率限制及基本反垃圾欄位，後台資料須登入才能存取。正式版要再設計管理者身分、資料備份與寄信服務；指定信箱是收件地址，寄件地址需使用可驗證的網域。

## 後台畫面

- **報名管理（已建）**：最近 200 筆報名列表、狀態變更、詳細資料與內部備註。課程篩選待加入。
- **聯絡訊息**：一般服務詢問列表與處理狀態。
- **課程管理**：編輯名稱、簡介、培訓重點、對象、排序，預覽後發布。
- **網站文案**：依頁面和區塊選擇鍵值，編輯短文案，預覽後發布。
- **文章管理**：建立草稿、分類、摘要、內文、封面，預覽後發布或下架。
- **通知紀錄**：查看寄信狀態與失敗重試結果。

## 實作順序與待確認資訊

1. 確認正式網站部署位置、可用的寄件網域及管理者登入方式。
2. 把本地 PostgreSQL 相容表結構遷移到正式 PostgreSQL，部署 API、登入與備份機制。
3. 上線報名 API 後驗證正式環境的送出、收件及錯誤流程，再加入郵件通知。
4. 增加一般聯絡訊息管理，以及課程、文案與文章的草稿／發布流程。

正式啟用前還需訂出報名資料保存期限，以及文章是否需要封面圖片上傳。**只把前端靜態檔案部署到線上時，報名與後台 API 無法運作；目前的本機資料與密碼不會被推送。**
